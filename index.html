How I ship

One change, many hospitals

Every hospital runs the same code. A change requested by one hospital must not change anything for the others, so each feature goes through the same steps.

  1. Design document firstWrite the analysis and design, confirm the business rules with the BA.
  2. Behind a config keyOff by default, so other hospitals keep today's behaviour.
  3. Additive migrationsNew Oracle columns and tables only; released scripts are never edited.
  4. Compatible APIsNew fields are optional, so older clients keep working.
  5. Test, then QAOffline harness, then the shared test environment, then hand over to QA.
